# YOLO 버전별 웹캠 성능 비교

웹캠 앞에 물체를 보여주고, **YOLO 모델 버전별로 얼마나 빨리, 얼마나 확실하게 인식하는지** 직접 측정한 벤치마크입니다.
[Ultralytics](https://github.com/ultralytics/ultralytics) 패키지로 모델을 불러와 같은 웹캠, 같은 방식으로 반복 측정했습니다.

## 비교한 모델

| 그룹 | 모델 |
|---|---|
| 이전 세대 경량 모델 | YOLOv5n(`yolov5nu`), YOLOv8n, YOLOv9t, YOLOv10n, YOLO11n |
| YOLO26 크기별 | YOLO26n, YOLO26s, YOLO26m, YOLO26l, YOLO26x |

## 모델 가중치 (.pt)

가중치 파일은 용량 문제로 레포에 포함하지 않았습니다. 스크립트의 `MODELS`에 적힌 파일명 그대로 ultralytics가 최초 실행 시 자동으로 내려받습니다. 측정에 사용한 파일은 다음과 같습니다.

| 모델 | 파일명 | 크기 |
|---|---|---:|
| YOLOv5n | `yolov5nu.pt` | 5.3 MB |
| YOLOv8n | `yolov8n.pt` | 6.2 MB |
| YOLOv9t | `yolov9t.pt` | 4.7 MB |
| YOLOv10n | `yolov10n.pt` | 5.6 MB |
| YOLO11n | `yolo11n.pt` | 5.4 MB |
| YOLO26n | `yolo26n.pt` | 5.3 MB |
| YOLO26s | `yolo26s.pt` | 19.5 MB |
| YOLO26m | `yolo26m.pt` | 42.2 MB |
| YOLO26l | `yolo26l.pt` | 50.7 MB |
| YOLO26x | `yolo26x.pt` | 113.2 MB (GitHub 파일 제한 100MB 초과) |

모델이 커질수록 파일 크기도 크게 늘어납니다. 인식 시간이 길어지는 결과와 같은 방향입니다.

## 측정 방법

세 가지 스크립트로 두 종류의 지표를 측정했습니다.

| 스크립트 | 측정 지표 | 방식 |
|---|---|---|
| `yolo_benchmark.py` | 추론 속도(ms, FPS), 평균 신뢰도, 프레임당 탐지 수 | 모델당 100프레임 연속 추론 (conf ≥ 0.4) |
| `yolo_benchmark_v2.py` | **인식 시간**, 성공률, 평균 신뢰도 | 물체를 숨겼다가 보여준 순간부터 첫 탐지까지의 시간을 15회 반복 (conf ≥ 0.5, 제한시간 5초) |
| `yolo_benchmark_26.py` | 위와 동일 (YOLO26 5종용) | 15회 반복 (conf ≥ 0.5, 제한시간 8초) |

- **인식 시간**: 시도를 시작한 뒤 신뢰도 임계값을 넘는 탐지가 처음 나올 때까지 걸린 시간(초). 제한시간 안에 못 찾으면 실패로 기록합니다.
- **성공률**: 전체 시도 중 제한시간 안에 인식한 비율.
- **평균 신뢰도**: 성공한 시도에서 가장 높았던 탐지의 confidence 평균.

## 결과

원본 CSV는 [`results/`](results) 폴더에 있습니다.

### 1. 추론 속도 (`results/yolo_benchmark_20260715_004540.csv`)

100프레임 평균. 속도는 `yolov8n`이 가장 빨랐고 `yolov9t`가 가장 느렸습니다.

| 모델 | 추론 시간 (ms) | FPS | 평균 신뢰도 | 프레임당 탐지 수 |
|---|---:|---:|---:|---:|
| YOLOv5n | 233.96 | 4.27 | 0.128 | 0.28 |
| **YOLOv8n** | **197.81** | **5.06** | 0.301 | 0.54 |
| YOLOv9t | 314.02 | 3.18 | 0.938 | 1.00 |
| YOLOv10n | 213.33 | 4.69 | 0.326 | 0.54 |
| YOLO11n | 224.93 | 4.45 | 0.257 | 0.55 |

> 이 표의 평균 신뢰도는 **탐지가 없는 프레임을 0으로 포함해** 평균낸 값입니다. 그래서 값이 낮은 모델은 "신뢰도가 낮다"기보다 "물체를 놓친 프레임이 많다"에 가깝습니다. 이 한계 때문에 이후 실험에서 인식 시간 방식으로 측정 방법을 바꿨습니다.

### 2. 인식 시간 (이전 세대 경량 모델)

**15회 반복** (`results/yolo_benchmark_20260715_182716.csv`)

| 모델 | 성공률 | 평균 인식 시간 (초) | 평균 신뢰도 |
|---|---:|---:|---:|
| YOLOv5n | 100% | 0.488 | 0.577 |
| YOLOv8n | 100% | 0.400 | 0.574 |
| YOLOv9t | 93% | 1.168 | 0.715 |
| YOLOv10n | 100% | 0.312 | 0.623 |
| **YOLO11n** | 100% | **0.178** | **0.771** |

**5회 반복 (사전 테스트)** (`results/yolo_benchmark_20260715_174235.csv`)

| 모델 | 성공률 | 평균 인식 시간 (초) | 평균 신뢰도 |
|---|---:|---:|---:|
| YOLOv5n | 100% | 0.499 | 0.516 |
| YOLOv8n | 100% | 0.503 | 0.458 |
| YOLOv9t | 100% | 0.366 | 0.609 |
| YOLOv10n | 40% | 4.345 | 0.405 |
| YOLO11n | 100% | 0.173 | 0.611 |

두 실험 모두 YOLO11n이 가장 빠르고 신뢰도도 높았습니다. 반면 YOLOv10n은 5회 실험에서 성공률 40%였다가 15회 실험에서는 100%로 올라, **시도 횟수가 적으면 결과가 크게 흔들린다**는 점도 확인했습니다. 15회 결과를 기준으로 보는 것이 안전합니다.

### 3. 인식 시간 (YOLO26 크기별)

**15회 반복** (`results/yolo_benchmark_20260717_134117.csv`)

| 모델 | 성공률 | 평균 인식 시간 (초) | 평균 신뢰도 |
|---|---:|---:|---:|
| YOLO26n | 100% | 1.230 | 0.952 |
| **YOLO26s** | 100% | **0.744** | 0.955 |
| YOLO26m | 100% | 1.391 | 0.957 |
| YOLO26l | 100% | 1.812 | **0.978** |
| YOLO26x | 100% | 3.053 | 0.971 |

- 모든 크기가 100% 성공했고, 신뢰도는 0.95 이상으로 높았습니다.
- 모델이 커질수록(`s` → `m` → `l` → `x`) 인식 시간이 길어지고 신뢰도는 소폭 올라가는 **속도-신뢰도 트레이드오프**가 보입니다.
- `n`이 `s`보다 느리게 나온 것은 예상과 다른 결과입니다. 시도 횟수가 15회뿐이라 편차의 영향일 수 있어 재측정이 필요합니다.

## 정리

| 목적 | 결과상 추천 |
|---|---|
| 가장 빠른 인식 (이전 세대 경량 모델 중) | **YOLO11n** (0.178초, 성공률 100%, 신뢰도 0.771) |
| 크기별 비교에서 균형 | **YOLO26s** (0.744초, 100%, 신뢰도 0.955) |
| 신뢰도 우선 | YOLO26l (0.978), 단 인식 시간 1.8초 |

## 실행 방법

Windows 기준입니다.

```bash
# 1. 가상환경 생성 및 활성화
python -m venv yolo_test
yolo_test\Scripts\activate

# 2. 패키지 설치 (최소: ultralytics, opencv-python)
pip install ultralytics opencv-python
# 또는 측정 당시 환경 그대로 설치
pip install -r requirements.txt

# 3. 실행 (웹캠 필요)
python yolo_benchmark_v2.py     # 이전 세대 경량 모델 인식 시간
python yolo_benchmark_26.py     # YOLO26 크기별 인식 시간
python yolo_benchmark.py        # 추론 속도(FPS) 측정
```

- 모델 가중치(`.pt`)는 최초 실행 시 자동으로 다운로드되므로 레포에는 포함하지 않았습니다. (`yolo26x.pt`는 약 118MB로 GitHub 파일 제한 100MB를 넘습니다.)
- 인식 시간 측정은 매 시도마다 **물체를 카메라 밖에 숨기고 Enter → 즉시 물체를 보여주는** 방식입니다. 모델마다 같은 물체와 같은 구도를 유지해야 공정합니다.
- 결과는 실행 시각이 붙은 CSV(`yolo_benchmark_YYYYMMDD_HHMMSS.csv`)로 저장됩니다.
- 스크립트 상단의 `MODELS`, `TRIALS_PER_MODEL`, `TIMEOUT_SECONDS`, `CONF_THRESHOLD` 값을 바꿔 조건을 조정할 수 있습니다.

## 한계 및 주의사항

- **실험 간 직접 비교 금물**: 이전 세대 모델(7/15)과 YOLO26(7/17)은 다른 날, 다른 제한시간(5초/8초)에 측정했고 물체와 조명도 같다는 보장이 없습니다. 신뢰도 값이 YOLO26 쪽에서 전반적으로 높은 것도 모델 차이인지 조건 차이인지 구분할 수 없습니다. 비교는 **같은 표 안에서만** 해석하세요.
- **표본이 작음**: 모델당 시도는 15회이며, 사전 테스트에서 보듯 결과가 달라질 수 있습니다.
- **인식 시간에는 추론 지연이 포함됨**: 큰 모델은 한 프레임을 처리하는 데 더 오래 걸리므로 첫 탐지까지의 시간이 길어지는 효과가 섞여 있습니다. 순수 "인식 능력"만의 차이는 아닙니다.
- **정답 라벨 없음**: 성공 여부는 어떤 클래스든 임계값을 넘는 탐지가 나오면 성공으로 처리합니다. 엉뚱한 물체를 잘못 인식한 경우도 성공에 포함될 수 있고, mAP 같은 정식 정확도 지표는 아닙니다.
- 측정에 사용한 PC 사양(CPU/GPU)은 기록하지 않았습니다. 절대적인 시간 값은 환경에 따라 달라집니다.
